# AW Unified SQLite + V10 Bridge Candidate — Arabic

## طريقة التشغيل الأولي
1. فك ضغط الحزمة كاملة داخل مجلد واحد.
2. افتح `index.html` بنفس الطريقة التي نجحت مع حزمة SQLite السابقة.
3. لا تنقل ملف HTML وحده؛ يجب أن تبقى `sql-wasm.js` و`sql-wasm.wasm` و`pako.min.js` و`aw-v10-bridge-v2.js` بجانبه.
4. احتفظ بنسخة احتياطية قبل أي اختبار كتابة أو ترحيل. لا تحذف بيانات المتصفح/التطبيق.

## ما تم جمعه
- واجهة مرشحة تتضمن إضافة مرجع سكربت `aw-v10-bridge-v2.js` إلى المصدر.
- أصول SQL.js وWASM وPako التي اجتازت فحوص البصمات/الملف في تقرير إصلاح SQLite.
- الجسر V2 واختبار الدخان والتقارير.
- حزمة النواة الخلفية الأصلية كأرشيف مستقل.
- نسخة المصدر الأصلية دون تعديل باسم `ORIGINAL_SOURCE_PRESERVED.html`.

## حدود مهمة
هذه حزمة مرشحة موحدة للواجهة والأصول والجسر، وليست نظام مزامنة إنتاجيًا مكتملًا. تضمين الخادم داخل ZIP لا يشغّله ولا ينشره. لم يُثبت اتصال حي بـ PostgreSQL، أو ترحيل بيانات، أو ربط outbox، أو مزامنة متعددة الأجهزة، أو اختبار APK فعلي لهذه الحزمة. الجسر لا يبدأ إرسال المستندات تلقائيًا؛ لا تفعّل الترحيل أو الكتابة الإنتاجية قبل إعداد الخادم وربط معرفات الشركة والحسابات واختبارات staging.

## التحقق
- فُحصت سلامة ملفات ZIP المصدرية أثناء قراءتها.
- جرى الحفاظ على المصدر الأصلي داخل الحزمة كملف منفصل.
- يلزم إعادة اختبار فتح `index.html` بعد فك الحزمة، لأن تجربة المستخدم السابقة تخص حزمة SQLite المنفصلة وليست دليلًا على اختبار هذه الحزمة الموحدة.
